## 如何替换桌面项目

1. 先备份桌面【诗词 1.0】实际文件夹。`.lnk` 是快捷方式，不是源码。
2. 本包 `shici/` 是完整前端。微信开发者工具直接导入此文件夹（里面有 `app.json` 和 `project.config.json`），或把它的内容覆盖到原项目中含 `app.json` 的前端目录。不要误把整个 `shici` 嵌进原 `shici` 再导入上一层。
3. 本包 `backend/` 是完整后端，必须同步部署。保留你自己服务器上的环境变量，不需要把任何真实 `.env` 上传 GitHub。
4. 本包未直接修改你电脑桌面文件，也未自动推送仓库或更新 Render 服务。不要将源码验证通过理解为线上已更新。

## Render 后端更新

- 当前仓库内实际后端路径为：`诗词小程序完整代码/小程序源码/backend`。
- 如果仍保留这个目录层级，Render 的 Root Directory 应指向上述完整路径。
- 如果你把本包的 `backend`、`shici` 放到仓库根目录，Root Directory 则填 `backend`。两种结构选其一，路径必须与仓库实际一致。
- Build Command：`pip install -r requirements.txt`
- Start Command：`uvicorn main:app --host 0.0.0.0 --port $PORT`
- 环境变量保持原模型配置。路线编排不依赖模型密钥；原有资料问答按原设计使用服务端模型或资料摘录。
- 默认请求地址仍为 `https://shici-skd1.onrender.com`，见 `shici/utils/config.js`。若更换后端域名，应同时修改该文件和微信 request 合法域名。
- 部署成功后，访问 `/` 应看到 `version: 0.5.0-henan-eight-cities` 和包含8城的 `travel_cities`；访问 `/api/travel/cities` 应得到8城目录。否则不要只凭小程序菜单判断上线完成。

1. 首页 → 一日诗旅 → 新密 → 生成：应出现新馆、密县县衙、溱洧水城，诗文为《溱洧》。
2. 切换新乡：应出现辉县百泉与苏门山啸台，不应残留新密景点。
3. 选郑州，日期选2026-11-02（周一）：应移除商都遗址博物院并显示调整说明。
4. 选荥阳 → 保存 → 切换洛阳 → 查看本机保存：应恢复荥阳；分享后打开也应落在荥阳。
5. AI问答：“推荐巩义一日诗旅路线，轻松一点”；应返回故里与石窟，带来源和路线详情入口。
6. AI问答：“推荐新乡轮椅无障碍诗旅”；应提示现有规则不能可靠满足，不强行给登台线路。
7. 洛阳龙门主题仍按西山→东山→香山寺→白园顺序。

## 实施边界

- 是依据资料的规则编排，不是实时地图最优路径；无内置实时导航、购票和天气接入。
- 来源点击复制链接，用户可在浏览器复核；不保证所有外站长期可访问。
- 新增七城各先提供一条经整理主题路线，不把同一路线包装成多个独立主题。
- 路线数据独立于原问答资料库。`poems.json` 原21条资料问答记录没有扩充为200条；本次新诗文可在路线详情阅读，不代表已全部接入独立诗词问答检索。
- 原有印章、积分等功能沿用；本次没有新增八城GPS打卡或积分兑换系统。
- 本机仅保存最近一条路线，加载时带复核提醒；不作云端账号同步。
- 本次未在微信开发者工具和手机真机上编译运行，须按上方操作验收。
