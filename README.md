# 诗行中原

## AI诗词问答与洛阳诗旅推荐小程序

**问一句诗，寻一段文脉，走一程中原。**

“诗行中原”面向诗词学习者、文化旅游爱好者及来豫游客，将诗词阅读、资料问答、文化点位与旅行路线连接起来。项目以微信小程序为载体，以洛阳为诗旅推荐试点，让用户从理解诗句进一步了解城市文化，并获得带有诗词依据、参观提醒和资料来源的一日行程建议。

本仓库用于学科竞赛作品展示与代码查阅，包含小程序前端、后端服务、结构化资料及测试记录。当前交付代码版本为 1.0；部分页面和接口文档沿用开发阶段名称“中原诗旅智导”或“中原诗词·行走河南”，均对应本项目。

## 项目定位与应用场景

诗词学习与文化旅游中，用户常遇到三个具体问题：诗句、注释及背景资料分散，查询后仍需辨别依据；能够读懂诗词，却不清楚它与河南地域文化的关系；想循着诗词游览城市，但缺少将诗文、景点和参观条件组织起来的行程建议。

项目围绕这些问题，提供“读诗—问诗—查看关联—生成路线—完成研学任务”的使用流程。当前以已整理资料和洛阳试点为基础，探索人工智能辅助诗词学习及地方文化旅游服务的应用方式。

## 作品特色

### 1. 回答附依据，便于核查

系统从项目资料中检索相关诗词，由模型辅助选择事实条目，再由后端校验并绑定来源输出。资料不足或创作背景尚未核实时，会说明依据边界；参考链接可复制到浏览器进一步核查。

### 2. 说明诗词与地点“怎样相关”

路线明确区分题咏地关联、诗人纪念地关联和主题配读。例如，白园作为白居易纪念地纳入行程；《春夜洛城闻笛》与洛邑古城的配对属于城市主题研学设计。系统不会据此将现代景区确定为诗歌写作现场。

### 3. 从资料查询衔接到旅行体验

问答结果可跳转到路线详情。每站提供诗词原文、白话解释、关联说明、研学任务、停留建议与参考来源，便于把线上学习带入城市参访。

### 4. 将参观约束纳入路线编排

龙门路线遵循资料中记载的西山石窟、东山石窟、香山寺、白园单线顺序；涉及洛阳博物馆的周一行程按通常闭馆规则保守调整。相关规则仍需结合场馆当日公告确认。

## AI问答与路线编排方案

项目采用微信小程序与Python后端协同实现。后端通过兼容OpenAI协议的接口调用通义千问模型，代码默认模型为 `qwen3.5-plus-2026-02-15`，实际模型可由服务端环境变量配置。

**诗词资料问答流程：**

1. 用户输入诗名、作者、诗句或相关问题。
2. 后端按照标题、诗句、作者及地域关键词检索结构化诗词记录。
3. 模型从检索资料中选择能够回答问题的事实条目编号。
4. 后端校验编号，输出已有资料内容并附上对应来源。
5. 没有足够资料时提示依据不足；模型不可用时，可返回明确标注的资料摘录。

**诗旅推荐流程：**

1. 用户通过表单选择偏好，或通过问答入口提出常见出游需求。
2. 后端根据主题、节奏、日期与已整理的点位资料编排行程。
3. 返回景点顺序、诗词、关联类型、研学任务、用时预算和参观提醒。
4. 小程序展示路线，并支持复制、保存与分享。

问答采用模型辅助证据选择；路线采用核查资料与规则编排。当前版本使用关键词检索和常见出游意图识别，尚未采用向量数据库或知识图谱。短期问答上下文仅保存最近诗词编号，不保存完整对话历史；路线偏好通过详情页表单调整。

## 运行方式

### 小程序前端

1. 下载或克隆仓库，在微信开发者工具中导入 **`shici/` 文件夹**。
2. 使用有权限的AppID配置，编译并打开首页。
3. 服务地址统一设置在 `shici/utils/config.js`。交付版配置指向 `https://shici-skd1.onrender.com`；实际演示可用性以服务运行状态为准。
4. 使用自己的后端时，修改 `API_BASE`，并在微信小程序后台配置相应的HTTPS request合法域名。
5. 通过开发者工具预览进行手机端检查；评委体验版需由团队上传并配置体验权限。

前端不存放模型密钥。首次请求可能遇到服务唤醒等待，失败时可通过页面重试。

### 后端本地运行

建议使用Python 3.11或以上版本。在仓库根目录安装依赖：

```bash
python -m venv .venv
```

激活虚拟环境：

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# macOS / Linux
source .venv/bin/activate
```

安装依赖并启动：

```bash
python -m pip install -r backend/requirements.txt
python -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

需要调用模型时，在 `backend/.env` 或服务端环境变量中配置：

```dotenv
DASHSCOPE_API_KEY=YOUR_MODEL_API_KEY
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen3.5-plus-2026-02-15
```

未配置模型密钥时，诗词问答使用资料摘录模式；规则编排的路线接口仍可运行。配置的模型需具有相应账号权限。

本地启动后，打开 `http://127.0.0.1:8000/docs` 查看接口文档。手机不能通过手机自身的 `127.0.0.1` 访问电脑服务，真机演示应使用可访问的HTTPS后端。

### 现有Render部署配置

- Root Directory：`backend`
- Build Command：`pip install -r requirements.txt`
- Start Command：`uvicorn main:app --host 0.0.0.0 --port $PORT`

## 主要接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/` | 服务版本、问答资料数量与功能状态 |
| POST | `/api/poetry/ask` | 诗词问答及常见洛阳出游问题 |
| POST | `/api/travel/recommend` | 洛阳一日路线推荐 |

问答请求示例：

```json
{
  "question": "《秋思》的开封是开封市吗？",
  "conversation_id": ""
}
```

路线请求示例：

```json
{
  "city": "洛阳",
  "days": 1,
  "theme": "tang",
  "pace": "light",
  "origin": "longmen_station",
  "travel_date": ""
}
```

`theme`支持`tang`、`history`、`landscape`；`pace`支持`light`、`full`；`origin`支持`hotel`、`longmen_station`、`luoyang_station`、`old_town`。日期可为空或使用`YYYY-MM-DD`格式。出发地点用于首程提醒，不代表实时交通计算。

接口使用`code`、`message`、`data`结构；问答数据包含`answer`、`sources`、`conversation_id`，识别到适用的路线需求时还可返回`route`。更多实现说明见 [后端README](backend/README.md)。

## 当前使用边界

- 问答内容以已接入资料为依据，未知创作年份、精确位置等信息需进一步核实。
- 当前路线试点为洛阳一日游；自然语言识别覆盖常见说法，复杂条件请在表单中确认。
- 停留与转场时间为项目预算，含午餐休息，不含首程和返程；开放、票价、预约及临时关闭以官方公告为准。
- 现阶段未接入实时导航、路况、天气、票务库存或支付服务；不提供无障碍条件保证。
- 保存、打卡及集章主要使用本机存储；暂无跨设备账户同步。

## 比赛期间的进一步计划

1. **扩充并校验诗词资料库。** 继续筛选与河南及中原文化有明确关联的诗词，统一整理原文、作者、注释、解释、背景和来源；逐项核验后分批接入，暂不能确认的信息标注待核实。
2. **拓展河南城市诗旅。** 在洛阳试点基础上，逐步增加巩义、荥阳、新乡等地的推荐内容，核实诗词与景点的关系、参观条件与行程顺序。
3. **改进需求识别与使用体验。** 完善条件确认、问答与路线跳转、失败提示及手机端展示，减少需求与推荐结果不一致的问题。
4. **补充质量验证。** 依据问答测试题、资料核查与实际体验记录持续修订，形成可供比赛展示和答辩复查的成果。

上述城市扩展与资料增量为后续计划，不计入当前已实现功能。
